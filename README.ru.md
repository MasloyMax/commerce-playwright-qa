# Commerce Playwright QA

Учебный проект для портфолио Automation QA: автоматизация интернет-магазина на **Playwright + TypeScript**. В репозитории есть собственный локальный стенд; чужие сайты, аккаунты и платежи не нужны.

## Запуск

Требуется Node.js 24. В каталоге проекта:

```powershell
npm ci
npx playwright install chromium firefox
npm run check
npm test
npm run test:report
```

Тестовый сервер запускается автоматически. Порт 4173 должен быть свободен.
Для ручного просмотра: `npm start`, затем http://127.0.0.1:4173.
Демонстрационные данные входа уже заполнены.

## Что показать работодателю

22 сценария запускаются в Chromium, Firefox и мобильном Chromium: вход, поиск и сортировка, корзина, заказ, изоляция сессий, восстановление после HTTP-ошибок, axe и клавиатура. Сумма заказа подтверждается отдельным запросом API.

Архитектура: сценарии → fixtures → Page/Component Objects и API helper → HTTP-приложение.
Названия сценариев, групп и хуков написаны на русском; ID проверок и метки `@smoke` сохранены.

## Устройство тестов и очистка

- `LoginPage` и `StorePage` открываются методом `open()`. Локаторы и действия находятся в Page Object, элементы корзины — в `CartComponent`, бизнес-проверки — в сценариях.
- Фикстуры создают объекты страниц и API-клиент. Предусловия явно заданы в `beforeEach`: вход через API и открытие магазина либо открытие формы входа без авторизации.
- В каждой спецификации `afterEach` завершает серверную сессию через API, включая сессии, созданные входом через UI. Ответ `401` допустим для гостя и после уже выполненного выхода.
- После `afterEach` встроенные фикстуры Playwright автоматически закрывают страницы и контекст теста, в том числе при падении. Сам браузер общий для тестов одного worker и закрывается при завершении worker. Поэтому `browser.close()` в `afterEach` не вызывается. Подробнее: [жизненный цикл фикстур Playwright](https://playwright.dev/docs/test-fixtures#execution-order).
- Дополнительный контекст в проверке изоляции сессий принадлежит фикстуре `secondSessionApi`: она завершает сессию и закрывает контекст в `finally`.

В тестах нет произвольных sleep и скрывающих сбои повторов. Проверки отказов устанавливают перехват запросов до действия, которое должно завершиться ошибкой.

## Границы

Это собственный учебный стенд с данными в памяти. Нет реального эквайринга, склада и промышленной авторизации. Проверки доступности автоматические и не заменяют ручной аудит. Мобильный запуск использует эмуляцию. Проект не следует описывать в резюме как коммерческий опыт.
